# 决策记录

**准入门槛**(三条全满足才写进来):

1. 属于 **架构 / 需求边界 / 安全策略 / 验证策略** 之一
2. 已被采纳(不是候选、不是猜测、不是"以后再定")
3. 会约束未来工作(不记录的话,未来某个改动可能无意违背它)

**不写进来的**:临时操作与救火(钉版本、临时开关)、未验证的猜测、代码里显而易见的事实、一次性事件。

本文件分两类:

- **前提 P-x**——从上游或代码继承的既定约束。不需要论证理由,只说明**动它要付什么代价**。
- **决策 D-x**——经确认采纳、会约束未来工作的选择。**新增前必须先提出并获确认**,未采纳的不写。

不在本文件的临时事项:钉 runner 版本的理由在 `ci.yml` 注释里;重做商店营销图在 `STORE_SUBMISSION.md` 的待办里。

## 前提(改动等于踩地基,走高风险流程)

### P-1 · 聊天界面用 iframe 承载官方页面
- **内容**:侧边栏内嵌 `chat.deepseek.com` / `chatgpt.com`,通过 DOM 与消息操纵,不自己实现聊天 UI。
- **动它的代价**:登录、会话、上传、流式回复都要自己重建并长期跟随官方 API;等于换一个项目。
- **相关**:`src/sidebar.html` 的 iframe、`src/content/chat-bridge.js` 全部交互。

### P-2 · 用 DNR 剥离三个聊天域的 `X-Frame-Options` / CSP
- **内容**:`rules.json` 是**三条**同构规则,分别作用于 `chat.deepseek.com`、`chatgpt.com`、`chat.openai.com`;**仅 `sub_frame` 请求**,移除 `x-frame-options` 与 `content-security-policy`。
- **动它的代价**:删掉任一规则,对应服务的侧边栏直接白屏(REVIEW.md 第 1 节失败项)。「只对 sub_frame 生效」是权限范围的关键,**写商店材料时不许说成"只针对 chat.deepseek.com"**——那三处失实陈述已修正过一次。
- **相关**:`rules.json`、`manifest.json` 的 `frame-src`、`STORE_SUBMISSION.md` 的权限说明与认证备注。

### P-3 · 上游 MIT 版权必须保留
- **内容**:`LICENSE` 同时保留 `Copyright (c) 2026 lllhcbjj` 与本 fork 的修改声明;`NOTICE` 写明谱系。
- **动它的代价**:删掉即违反 MIT,不构成可讨论的选项。

### P-4 · 测试用 mock 站点,不对真实站点跑
- **内容**:`tests/functional.test.js` 用 `context.route` 拦截三个站点。
- **动它的代价**:换成真实站点会引入登录态、限流、随机失败;**必须新增独立用例集,不许替换现有 mock**。
- **已知代价**:真实站点改版时 CI 永远是绿的。

## 决策

### D-1 · 扩展改名为「AI 侧边栏增强版(Unofficial)」
- **依据**:自己维护、自己发布,标题带 DeepSeek 商标会被审核要求授权证明;同名条目也会造成重名混淆。
- **放弃**:保留原名(改动最小,把商标与重名风险留给未来)。
- **约束未来**:显示名不带第三方商标;描述里保留 DeepSeek / ChatGPT 作兼容性说明(合理使用)。
- **日期**:2026-10-29

### D-2 · 发布者身份为 MBriad,仓库与政策页都指向本 fork
- **依据**:此后由本人维护发布,联系方式必须是能真正响应的人。
- **放弃**:沿用上游链接(等于让用户把问题报给不再维护的人)。
- **约束未来**:Issues / 仓库 / 隐私政策 URL 一律指 `MBriad` 与 `mbriad.github.io`,新文档不得再引入上游联系方式。
- **日期**:2026-10-29

### D-3 · trunk-based:`main` + 短分支 + squash + tag,不建 `dev` / `release` 常驻分支
- **依据**:单人维护、无后端、无数据迁移、分发物是静态 zip,回滚近乎免费。三支模型解决的是"多人并行 / 发布冻结 / 线上环境"三个不具备的问题,而长期分支的合并冲突成本是实打实的。
- **放弃**:`dev` / `release` / `main` 三支模型。
- **约束未来**:不新增长期存活的分支;发版只靠 tag;hotfix 从 tag 临时开分支,用完删除。
- **重新考虑**:出现第二个维护者,或上商店后需要长期并行"审核中版本"与"开发版本"(届时仍只需 hotfix 分支)。
- **日期**:2026-10-29

### D-4 · 修 bug 的固定形态:一条复现测试,不堆测试
- **依据**:改动小才审得动。堆测试会把 bug fix 变成小型重构,风险与 review 成本都翻倍。
- **放弃**:"顺手提高覆盖率"。
- **约束未来**:先写一条能复现的测试让它红 → 修到绿 → 收工;禁止补无关模块、顺手重构、把测试改成迎合当前实现。
- **日期**:2026-10-29

### D-5 · 评审规则按模块拆分,`AGENTS.md` 只留项目事实与工作规则
- **依据**:两类东西混在一起——"项目是什么"是稳定事实,"怎么审这部分代码"要随代码演进;而且评审口径必须由所有者按模块撰写,agent 不能替自己定标准。混写会让规则文件膨胀到没人读。
- **放弃**:全塞进 `AGENTS.md`;也放弃"全仓库一份 `docs/REVIEW.md`"(那样 platform / content / verification 三块的口径会被埋在一份文件里)。
- **约束未来**:`REVIEW.md` 是**按模块各一份**:根 `REVIEW.md`(平台)、`src/REVIEW.md`(扩展页)、`src/content/REVIEW.md`(内容脚本)、`tests/REVIEW.md`(验证)、`docs/REVIEW.md`(文档与根级 markdown);改评审口径只动对应那份。
- **例外**:根 `REVIEW.md` 虽在根目录,但归**平台**模块,不归文档模块;改任一口径文件时按该文件自己的口径审。
- **已知违规**:`AGENTS.md` 现为 **178 行**,已超本文自己定的 120 行阈值。**拆分尚未完成**——在拆完之前不许再往里堆新规则。
- **日期**:2026-10-29

### D-6 · 评审发现必须打标签并逐条裁决,未裁决阻塞合并
- **依据**:风格类发现对 agent 作者成本极高——人会一秒挥掉一个 nit,agent 会去改,于是多一个 commit、多一轮评审。而老的 bug 不标出来,看起来像本次改坏的。
- **放弃**:只要求"逐条核实"(无法量化,靠自觉)。
- **约束未来**:每条发现带 `Critical` / `Nit` / `Pre-existing` 之一;`Critical` 未修不许合;`Pre-existing` 只记录不改;风格类由 reviewer 自己丢弃不报。标签与 reviewer 输出一律英文。
- **修订(2026-10-30)**:标签由 `严重` / `一般` / `既存` 改为 `Critical` / `Nit` / `Pre-existing`,评审输出改为全英文。三分法的结构没变,只换名字与语言。
- **日期**:2026-10-29

### D-7 · 评审收敛:三轮封顶、首轮后只审新 diff、按类整修、不重复报
- **依据**:agent 作者 + agent reviewer 可以互相拖住无限轮。已知案例有 PR 一夜跑了 50 多轮;被反复指出的代码里约 59% 在首轮之前就已存在。
- **放弃**:不限轮次、每次都全量重审。
- **约束未来**:第三轮后不再新增发现,改为"退一步重新考虑方案";同类问题第 3 次出现就改规则文件而不是再改代码。
- **日期**:2026-10-29

### D-8 · 批准只对一个 commit 有效
- **依据**:批准针对的是"我看到的这份代码"。之后任何新 commit(我 push,或手工解冲突)都不在批准范围内。
- **放弃**:一次批准覆盖整个 PR。
- **约束未来**:拿到"可以合"之后我又推了 commit,必须重新要批准,不许拿旧批准兜新代码。
- **日期**:2026-10-29

### D-9 · 纯文本 / 格式改动 = 低风险 = 0 人审批,证据只有 Markdown 与链接检查
- **依据**:这类改动不改变运行行为;人能看出来的东西(断链、标题层级、代码围栏)机器都能查,截图与人工确认在这里是纯摩擦。
- **放弃**:维持"低风险也要抽查一次"——代价是每次文档改动都要等人,收益接近于零。
- **约束未来**:低风险档不再要求人工确认,也不再要求截图;但 **Markdown 与链接检查必须绿**。检查未落地之前,这一档不许对外宣称 0 人审批。任何"给文档改动加人工确认"的提议,必须先推翻本条。
- **日期**:2026-10-30
