3权限怎么算：四层，逐层收窄

  1. 企业 / 组织 / 仓库的默认权限（Settings → Actions → General → Workflow permissions）
  2. Workflow 顶层的 permissions:
  3. Job 级的 permissions:（进一步收窄）
  4. Fork 来的 pull_request：写权限通常被降为只读

声明 ≠ 最终授予。没写 permissions 不等于只读，也不等于可写——取决于仓库默认值。

4最小权限：每个 job 只要它用得上的

Job A · 跑 PR 代码

contents: read，其余全 none。它不需要评论、不需要密钥。

Job B · 持密钥

contents: read + pull-requests: write。只够“读 diff、发评论”。

5两个容易混的点

一、token 权限 ≠ secrets。 token 被降成只读，不等于拿不到 secret；这两套是分开控制的。

二、fork 的 pull_request_target 不受降级约束。 它跑在 base 上下文，拿得到 secrets 和写权限——所以千万不能在它里面 checkout PR 代码再执行。

小练习：公开仓库 + 仓库默认 Read and write + on: pull_request + 声明 pull-requests: write + PR 来自公开 fork，能用 token 发评论吗？

不能。 声明的是“请求”，fork 来的 pull_request 会被降级成只读，写评论会 403。
